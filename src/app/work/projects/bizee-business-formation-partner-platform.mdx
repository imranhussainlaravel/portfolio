## Overview

Bizee's partner platform connects external business-formation partners to Bizee's services. Partners
submit and track business formations through an API and a dashboard, while the platform brokers
those requests to Bizee's internal systems and reports status back.

**Stack:** Laravel · PHP · MySQL · REST APIs · Webhooks

## What I built

### Partner-facing APIs

I developed the Laravel APIs partners integrate against, secured with Bearer-token authentication
so each partner's credentials scope what they can read and submit. The APIs integrate with Bizee and
Atomic internal systems, which meant the partner-facing contract had to stay stable even as the
internal services behind it changed shape.

### Partner dashboard

Alongside the API, I built partner dashboard functionality so partners who do not want a deep
integration can still submit and track formations through a UI backed by the same endpoints.

### Webhook communication with white-label companies

Business formation is not a synchronous operation - filings move through states over days. I worked
on webhook communication with white-label companies so status changes propagate outward as they
happen, rather than requiring partners to poll.

### Testing and integration

The work included business-formation testing and API integration across the partner and internal
boundaries - exercising the flows end to end against real internal systems rather than only against
mocks.

## Outcome

I architected and developed the partner-facing integration layer for Bizee, delivering secure REST APIs built on Laravel. I took full ownership of designing the Bearer-token authentication system, which rigidly scopes read and write permissions to each individual partner's credentials. To handle long-running, asynchronous business formation processes, I implemented a robust outbound webhook communication system that actively pushes status updates to white-label companies, eliminating the need for inefficient polling. I also engineered the partner dashboard to serve clients requiring a UI rather than direct API access. The most critical lesson from this development was that partner-facing API contracts must remain entirely decoupled and strictly stable, serving as a reliable boundary even when the underlying internal Bizee systems and services change shape over time.

**Key facts:**
- Stack: Laravel, PHP, MySQL, REST APIs, Webhooks
- Ownership: Partner-facing APIs, Bearer-token authentication, and dashboard backend
- Focus: Asynchronous white-label webhook workflows
