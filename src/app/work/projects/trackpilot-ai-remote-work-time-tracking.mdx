## Overview

TrackPilot AI is a production SaaS platform for remote-work tracking. Organizations set up
projects and tasks, freelancers track time against them through a desktop tracker, and the platform
turns the resulting screenshots, activity data, and timesheets into approvals, reports, and
invoices.

**Stack:** Laravel · MySQL · Next.js · Stripe · Firebase · AWS S3

## What I built

### Backend ownership

I owned backend development across the platform's core domains:

- Organizations and freelancer accounts
- Projects, tasks, and their assignment model
- Roles and permissions
- Time tracking, screenshots, and activity data
- Timesheets, approvals, and reporting

The interesting constraint here is write volume. A desktop tracker running for a full workday
produces a continuous stream of time entries, screenshots, and activity metrics per user. The data
model and storage strategy had to keep ingestion cheap while still supporting the aggregate queries
that reporting and timesheets depend on.

### REST APIs

I built the REST API layer consumed by two very different clients:

- The **Next.js dashboard**, which needs aggregated, permission-filtered views
- The **desktop tracker**, which pushes raw tracking data, screenshots, and activity metrics

Alongside those, the API surface covers subscriptions, administration, support, plans, and coupons.
Screenshot storage runs through AWS S3 rather than the application server, keeping large binary
uploads off the request path that handles tracking data.

## Outcome

I developed the core Laravel backend for TrackPilot AI, taking ownership of the system architecture from the data models to the REST APIs. I engineered the ingestion pipeline to handle continuous streams of time entries, screenshots, and activity metrics from the desktop tracker, ensuring the system remains stable under heavy write loads. Additionally, I built out the Stripe subscription lifecycle, implementing idempotent webhook handling to reliably synchronize billing states across the platform. The Next.js dashboard consumes these APIs to deliver aggregated, permission-filtered reporting to end users. The main lesson from this deployment was that strictly separating high-volume ingestion routes from the complex reporting queries is absolutely essential to prevent the tracking pipeline and the customer-facing dashboard from competing for the same database resources.

**Key facts:**
- Stack: Laravel, MySQL, Next.js, Stripe, AWS S3
- Ownership: Core backend architecture, REST APIs, and Stripe billing integrations
- Infrastructure: Handled high-volume time tracking and screenshot ingestion via S3
